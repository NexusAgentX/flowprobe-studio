# v0.1 — Architecture Proof

## Objective

Prove one complete vertical path through the chosen architecture before broad feature development.

The milestone succeeds when a deterministic test/event can travel through:

`Network Runtime boundary -> Capture Core -> NormalizedFlow -> Storage -> Desktop query/UI -> WASM Analyzer -> SemanticEvent`

and the same design has an integration proof for a real local HTTP/TLS flow where the development platform permits it.

## Required outcomes

- repository/toolchain builds reproducibly;
- desktop shell communicates with a non-renderer supervisor boundary;
- NetworkRuntime trait/interface plus sing-box adapter and fake runtime;
- config compiler protects `__flowprobe_*` namespace;
- Capture Core emits normalized connection/HTTP flow objects;
- local metadata store persists and queries flows;
- analyzer runtime loads a sandboxed demo plugin implementing the WIT contract;
- demo analyzer emits a deterministic semantic event from a fixture;
- simple Traffic UI proves query/detail path;
- CI validates contracts, formatting/lint/tests and forbidden shortcuts;
- end-to-end architecture test proves module composition.

## Non-goals

Do not turn v0.1 into the full product. Specifically defer:
- polished multi-platform installers;
- complete proxy subscription UX;
- production-complete TLS pinning handling;
- all protocol decoders;
- rewrite/breakpoint debugger;
- Codex-specific analyzer;
- Parquet/DuckDB.

## Exit criteria

All v0.1 task contracts are complete, CI is green, no protected architecture file was modified without an architecture task, and an independent verifier can run the milestone acceptance instructions from a clean checkout.

## Clean-checkout verification runbook

The deterministic architecture proof is an isolated Cargo package at
`tests/integration/v0_1`. Its own `[workspace]` and `Cargo.lock` keep it out of
the repository's virtual root workspace, whose membership is intentionally not
changed by INT-001. CI runs the package explicitly after the root Rust tests.

On a supported development checkout with mise installed and this repository
trusted, run:

```text
mise install
mise run bootstrap
mise run check
mise exec -- python -B -m unittest discover -s scripts/tests -p 'test_quality_gate.py'
mise exec -- python -B scripts/quality_gate.py
mise exec -- python -B scripts/check_v0_1_integration.py
```

These commands decide three separate bodies of evidence. `mise run check`
covers the root Rust workspace and desktop renderer. The next two commands make
the anti-shortcut gate's own tests and repository scan visible. The final
isolated release gate repeats those quality checks with the active Python
interpreter and bytecode disabled, verifies the independent Cargo lock file,
formatting, and clippy with warnings denied, then explicitly runs
`architecture_proof`, `tls_interception_proof`, and the real-proof binary's
curl-command unit tests before running every isolated target. Naming each proof
prevents deletion of a target from turning the all-targets command silently
green. The script resolves the repository root from its own location, so it
also works when invoked from another current directory. CI additionally runs
the root Rust workspace with `--locked` and verifies that a real curl executable
is present before this isolated gate.

The evidence must not be conflated:

- `architecture_proof` is a deterministic synthetic composition proof. It uses
  `FakeNetworkRuntime` and explicitly supplies synthetic TLS and HTTP bytes to
  Capture Core.
- `tls_interception_proof` is the generated-CA Capture Core proof. It performs
  authenticated downstream and upstream TLS entirely on loopback without
  sing-box, a proxy, TUN, or a system trust-store change.
- `prove_v0_1_local_network.py` is the separately invoked pinned-sing-box proof.
  It exercises a loopback HTTP proxy, HTTPS CONNECT, and an address-free direct
  outbound. It does not deliver traffic into Capture Core.

The real-proof binary has one curl command builder for both HTTP and HTTPS.
`--disable` is its first argument, before `--fail`, proxy, header, and `--cacert`
options, because curl only honors that curlrc opt-out in the first position.
This disables curl startup configuration; it does not claim to clear every curl
environment variable. A unit regression invokes an absolute executable that
identifies itself as real curl against a bounded loopback responder while
temporary `HOME`, `CURL_HOME`, `XDG_CONFIG_HOME`, `USERPROFILE`, and `APPDATA`
locations contain hostile `.curlrc`, `_curlrc`, and `curlrc` files. The
production invocation preserves the exact stdout and request headers. Removing
`--disable` or moving it to the second position demonstrably loads an
`--insecure`, header, and write-out canary configuration and makes the strict
output assertion fail. The responder has one total accept/read/write deadline
and a request-size limit; its thread is joined, and the temporary curlrc root is
explicitly removed and asserted absent.

The deterministic test first validates and starts a `FakeNetworkRuntime`
through `ConfigCompiler` and `Supervisor`. The runtime interface has no live
capture stream, so the test then explicitly supplies synthetic TLS and HTTP
bytes to the generic `CaptureCore`. It proves canonical `NormalizedFlow`,
opaque raw and normalized blob retention plus SQLite metadata, staged execution
of the checked-in demo analyzer component, commit only after successful WASM
completion, direct semantic storage query, and the `TrafficService` list,
detail, and semantic DTOs. Two clean executions must produce the same snapshot.
Separate adversarial cases prove that a guest trap, an output limit after a
first staged event, and a host rejection after a first staged event commit no
derived rows while leaving raw and normalized sources queryable.

The fixture uses conspicuous fake Authorization, Cookie, and body canaries. The
test confirms they exist in explicitly retained raw source bytes but not in the
ordinary normalized document, analyzer log output, or UI DTOs. It also checks
the exact ordinary DTO key sets, excludes payload references and analyzer
attributes from those DTOs, and verifies that opaque references contain no file
path syntax. No analyzer receives a SQLite handle or path.

## Generated-CA TLS interception proof

The isolated integration package also runs `tls_interception_proof`. Production
code in `flowprobe-capture-core` generates an in-memory path-length-zero CA,
issues a distinct short-lived leaf for the exact expected SNI, terminates the
downstream rustls session, and authenticates a separately certified loopback
origin before reading or forwarding the HTTP request. The test owns only the
loopback client and origin setup. It configures each TLS leg with an isolated
root store and obtains the negotiated version, ALPN, wire ClientHello,
decrypted request/response transcript, interception state, and HTTPS
`NormalizedFlow` from the production boundary rather than constructing them as
fixture input.

The proof checks one exact request/response relay, a client that trusts only the
generated interception CA, wrong-SNI and untrusted-client rejection, upstream
certificate rejection before the origin receives HTTP, bounded fragmented
ClientHello handling beyond the initial 4096-byte rustls buffer, multiple
records from one arrival, preservation of bytes prefetched after ClientHello,
mixed-case and absolute-name DNS identity equivalence, combined wire/plaintext
transcript backpressure where each input fits but their shared total does not,
and secret-safe Debug output.
It distinguishes a per-socket-operation idle timeout from one shared monotonic
whole-transaction deadline and proves that a slow trickle cannot refresh that
deadline. All sockets bind or connect only to `127.0.0.1`; the generated private
keys remain in process memory. The proof does not install a CA, change a system
trust store, configure a proxy or TUN, or contact an external endpoint.

This minimum boundary deliberately relays one bounded HTTP/1.1 transaction and
requires explicit response `Content-Length` framing. CA persistence/rotation,
installation UX, HTTP/2 relay, multi-transaction connections, pinning/fallback
policy, and live Network Runtime delivery remain later-milestone work.

## Real local HTTP/TLS proof

The real-runtime proof is explicit and is not part of bootstrap or CI. It needs
Python 3.12, Cargo/Rust 1.98.0, curl, OpenSSL, and a sing-box binary with version
`1.13.19` and revision
`b5ebaa1fc0f2b94256180b95468e73ef53caa27d`. It is fail-closed for exactly four
OS/architecture combinations and their extracted executable hashes:

| Host | Required sing-box binary SHA-256 |
| --- | --- |
| macOS arm64 | `5b75c1dec19488675f725adc7a6e3a7301a553117af835dc47669b1fa918976b` |
| macOS x86_64 | `078164e43464f2282ae526151411320582c3e60a0294cec24a627edf205305a6` |
| Linux aarch64 | `0bd9f22cd677d7fe70324944b3dfaf967971607ac3f713d1b754248d8b0d702d` |
| Linux x86_64 | `7e9dcd7239c49478a576d79f272751e5ed1c2aba7cc08ab1b2bd69c00c904ba1` |

The pins were derived from the corresponding official SagerNet v1.13.19 GitHub
release archives after their archive digests were independently checked. The
explicit mise `github:sagernet/sing-box@1.13.19` selector records that release
provenance; the repository-side executable SHA check is the byte-level
attestation used by both provisioning and proof, independently of the reported
version string. On a supported host, use this fail-closed decision sequence.

### Supported-host release-audit sequence

First prove that the required environment cannot be omitted. This command must
exit `1` with `required environment variable FLOWPROBE_SING_BOX_BIN is missing`
before hashing a binary, resolving curl/OpenSSL, starting Cargo, or creating
temporary origins:

```text
env -u FLOWPROBE_SING_BOX_BIN \
  mise exec -- python -B scripts/prove_v0_1_local_network.py --require-supported
```

Next provision and locate the pinned binary. Provisioning through mise is an
explicit opt-in operation:

```text
mise exec -- python -B scripts/provision_v0_1_singbox.py --require-supported
mise which sing-box --tool github:sagernet/sing-box@1.13.19
```

Before the positive network proof, run the SHA-negative mutation control with
the absolute path printed by the second command. This destructive-copy test
never modifies the provisioned binary or enters CI. It copies that valid binary
to a temporary directory, appends one byte, confirms the copy still reports the
pinned version, and requires the proof to reject it before resolving local
tools, starting Cargo, or creating origins:

```text
FLOWPROBE_SING_BOX_BIN=/absolute/path/to/sing-box \
  mise exec -- python -B scripts/test_v0_1_singbox_sha_negative.py
```

Only after that mutation control passes, run the positive local-network proof:

```text
FLOWPROBE_SING_BOX_BIN=/absolute/path/to/sing-box \
  mise exec -- python -B scripts/prove_v0_1_local_network.py --require-supported
```

The negative command must report `negative-proof-exit=1`,
`sha-mismatch-before-cargo-or-origins=passed`, and
`temporary-mutated-binary-cleanup=passed`. The positive command must report one
HTTP origin, one HTTPS CONNECT origin, `managed-configs-after-stop=0`,
`runtime-pid-file-after-stop=removed`, and `temporary-state-cleanup=passed`.

### Post-proof cleanup audit

The success markers above are the primary bounded-cleanup assertions. Finish
with these independent checks; each command must succeed:

```text
! ps -Ao command= | grep -E '[.]flowprobe-runtime-|[f]lowprobe-v0-1-real-singbox-proof'
test -z "$(find "${TMPDIR:-/tmp}" -maxdepth 1 \( -name 'flowprobe-v0-1-local-*' -o -name 'flowprobe-sha-negative-*' -o -name 'flowprobe-int-002-curlrc-*' \) -print)"
test -z "$(find . -type d -name __pycache__ -print)"
test -z "$(git status --short)"
```

They confirm that the proof left no managed-runtime or proof process, temporary
proof/curlrc directory, Python bytecode cache, or tracked/untracked checkout
diff.

Before executing the binary or creating origins, the script hashes it and
requires the platform-specific SHA-256 above, then verifies the pinned version
and revision. It prints expected and actual hashes plus a verified marker as
evidence. It creates temporary plain-HTTP and TLS origins on
`127.0.0.1`, an ephemeral self-signed certificate and mode-0600 private key,
and temporary runtime state and ports. The Rust proof uses the real runtime as
the `ConfigCompiler` validator, performs another explicit runtime validation,
then proves start, health, status, one HTTP request, one HTTPS CONNECT request,
stop, stopped status, and managed-config removal. Both curl requests use the
same explicit loopback HTTP proxy; HTTPS trusts only the ephemeral certificate
with `--cacert`.

The compiled proof configuration contains one `127.0.0.1` HTTP inbound, one
address-free direct outbound, and `set_system_proxy: false`. It contains no TUN
inbound, automatic routing, global CA installation, or external endpoint. A
`finally` cleanup stops both local origins; the Rust side also attempts runtime
stop during error unwinding. The Rust guard removes its process-group identity
file only after a successful stop; otherwise it leaves that identity for the
Python parent. A timeout terminates the proof's isolated process group, then the
parent uses the recorded runtime process group for bounded TERM/KILL cleanup,
refuses to target its own process group, and unlinks the identity only after the
group is gone. There is a residual operating-system race in which a numeric
process-group ID could be reused between child exit and the fallback probe; the
short handoff window and self-group guard reduce but do not eliminate that
risk.

This is evidence for the managed sing-box process/config boundary and direct
loopback HTTP/TLS proxying. It is not evidence for TUN capture, system-wide TLS
interception, an installed global CA, or live delivery from sing-box into
`CaptureCore`.

The real proof supports only macOS arm64/x86_64 and Linux aarch64/x86_64, where
both the pinned executable digest and POSIX process-group cleanup are defined.
Common `arm64`/`aarch64` and `x86_64`/`amd64` machine aliases are normalized.
Another OS or architecture exits 77; `--require-supported` converts that
condition into failure. On a supported combination, a missing environment
variable, binary, curl, OpenSSL, SHA/version/revision match, network step,
lifecycle assertion, or cleanup assertion is always a failure and is never
silently skipped.
