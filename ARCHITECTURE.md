# Architecture

## System decomposition

FlowProbe Studio has three independent planes plus a desktop supervisor/UI.

### 1. Network Plane — sing-box runtime

Responsibilities:
- TUN and OS routing integration;
- DNS and route rules;
- process-aware routing where supported;
- proxy protocols and nodes;
- selectors / URLTest groups;
- direct and external upstream egress;
- profile execution.

Boundary rule: sing-box is an **independent managed process/runtime**. Capture Core does not import sing-box packages or rely on undocumented internal APIs.

### 2. Capture Plane — Rust Capture Core

Responsibilities:
- receive original-destination streams from the Network Plane;
- TLS interception and pass-through policy;
- protocol detection/decoding;
- HTTP/1.x, HTTP/2, streaming protocols, generic connection metadata;
- normalized flows/events;
- raw capture/session recording;
- replay/debug primitives;
- sensitive-data handling.

Boundary rule: Capture Core must function with a fake network runtime and may not require sing-box-specific semantics.

### 3. Analysis Plane — WASM Analyzer Runtime

Responsibilities:
- execute analyzers in a sandbox;
- expose versioned host capabilities;
- enforce declared permissions;
- allow analyzers to consume normalized events/query allowed historical data;
- persist semantic events through host APIs;
- render analyzer-provided declarative views through the host UI.

Boundary rule: third-party plugins do not receive arbitrary filesystem/network/process execution by default and do not directly open the host database.

### 4. Desktop / Supervisor

Responsibilities:
- Tauri application shell and UI;
- privileged helper/service lifecycle;
- sing-box process lifecycle;
- config compilation;
- CA install/uninstall UX;
- crash recovery and network rollback;
- local IPC/RPC;
- application updates and diagnostics.

## Runtime data path

Conceptual capture path:

`Applications -> TUN -> Network Runtime -> Capture Core -> Network Runtime Egress -> Internet`

The implementation may use protected internal SOCKS/HTTP/IPC channels between sing-box and Capture Core. Those internal objects are generated by the Config Compiler and use reserved names beginning with `__flowprobe_`.

User configuration controls proxy behavior, nodes, groups, DNS, and routing, but cannot remove or redefine the protected internal capture plumbing.

## Configuration compiler

Final runtime configuration is produced as:

`System Base + User Profile + Runtime Overlay -> Validation -> Compiled sing-box Config`

System Base owns protected internal inbounds/outbounds/rules. User Profile owns ordinary sing-box behavior. Runtime Overlay contains ephemeral information such as ports, chosen interfaces, process exclusions, and capture-mode state.

Users must be able to inspect the compiled result. Invalid configurations fail before network routes are committed.

## Loop prevention

The system must prevent recursive capture of:
- FlowProbe's own runtime connections;
- Capture Core egress;
- locally detected external proxy process egress.

Preferred mechanism: process/path-aware routing to a direct outbound plus explicit physical-interface/default-interface handling. The exact per-OS implementation is abstracted behind Network Runtime capability reporting.

## Failure model

Network changes are transactional:
1. discover baseline network state;
2. validate configuration;
3. validate selected egress;
4. start internal services;
5. create TUN / install routes;
6. health-check end-to-end path;
7. commit active state.

Failure before commit rolls back. A watchdog/privileged helper must restore network state if the UI or engine crashes.

## Protocol model

The stable internal hierarchy is:

- L0 Packet / datagram metadata
- L1 Connection
- L2 Protocol event (TLS, HTTP, WebSocket, SSE, DNS, etc.)
- L3 Transaction / stream
- L4 Semantic event emitted by analyzers

Analyzer contracts start at L2/L3 and must not depend on TUN implementation details.

## Storage model

- SQLite: live metadata, settings, indexes, small semantic entities.
- Blob/session store: request/response payloads, stream chunks, raw captures; compressed and optionally encrypted.
- Parquet: later milestone for durable high-volume normalized/semantic event data.
- DuckDB: later milestone for local analytical queries over Parquet/session datasets.

Raw data is immutable source material. Derived semantic data is rebuildable from retained normalized/raw input.

## Security boundaries

- CA private keys never leave the local machine by default.
- privileged network/CA operations are isolated from the web UI renderer.
- payload capture is opt-in and time/size bounded.
- authorization/cookie material is redacted in ordinary views.
- WASM analyzers use capability-based permissions.
- active traffic mutation features are visibly separated from passive capture mode.

## Architecture changes

Accepted ADRs and files under `docs/contracts/` are protected architecture artifacts. Implementation tasks may not silently alter them. Any incompatible change requires a dedicated architecture task/ADR and migration plan.
